# V0.1 Stats Draft Mapping

This document maps design objects to hand-authored Stats drafts. These files are deliberately marked as drafts: BG3 Stats syntax is sensitive to inherited entries, functor signatures, resource UUIDs and base-game identifiers, so fields that cannot be verified from official documentation alone must be cloned from known-good Toolkit records before shipping.

## Known validation gates

1. `QTD_SageQi` must be created in ActionResourceDefinitions and referenced using the resource identifier/UUID format generated by Toolkit.
2. Somersault Cloud must clone a known-good teleport spell rather than relying on guessed teleport functor syntax.
3. Sea-Calming Strike needs a known-good weapon-damage and Strength-saving-throw implementation before its knockback is finalized. `DealDamage` and `Force` themselves are documented functors, but their conditional use still needs a known-good template.
4. Fiery Golden Eyes must validate how See Invisibility / invisibility suppression and attacker-specific Advantage are represented in current Toolkit data.
5. Ruyi Mastery must validate the supported way to choose Strength or Dexterity for the quarterstaff attack roll without globally changing other weapons.
6. Golden Armor and Cloud-Walking Boots need actual GustavDev/base-game Parent records selected inside the Toolkit Stats Editor.
7. The boots' once-per-short-rest free Somersault Cloud remains disabled until a validated cooldown/unlock pattern is cloned.

## Rule

Anything labelled `TODO_TOOLKIT_CLONE` or described as a validation gate is not considered runtime-ready until copied from a working base-game record in BG3 Toolkit and re-tested in `Basic_Level_A`.
